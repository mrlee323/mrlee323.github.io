## this가 이렇게 설계된 이유

대부분의 언어에서 `this`는 "이 메서드가 속한 인스턴스"입니다. 클래스에 메서드가 묶여 있으니 선언 위치만 보면 `this`가 무엇인지 알 수 있습니다.

자바스크립트는 다릅니다. 함수는 어떤 객체에도 속하지 않는 독립된 값입니다. 같은 함수를 여러 객체에 붙여 쓸 수 있고, 변수에 담아 넘길 수도 있습니다. 그렇다면 함수 안의 `this`는 **함수가 실행되는 순간에 정해질 수밖에 없습니다.**

> this는 함수의 속성이 아니라 **호출(call)의 속성**이다.

헷갈리는 이유는 코드가 클래스 문법처럼 보이는데 실제 규칙은 "호출 방식"에 있기 때문입니다. 눈은 선언 위치를 보고, 엔진은 호출 위치를 봅니다.

## 내부 동작 방식

### 호출 시점에 바인딩이 결정된다

함수가 호출되면 새 실행 컨텍스트가 만들어지고, 이때 `ThisBinding`이 함께 설정됩니다. 어떤 값이 들어가는지는 호출 형태가 결정합니다.

| 호출 형태 | this |
|---|---|
| `fn()` | `undefined` (strict) / `globalThis` (sloppy) |
| `obj.fn()` | `obj` |
| `new Fn()` | 새로 만든 객체 |
| `fn.call(x)` / `apply` / `bind` | `x` |
| 화살표 함수 | 자기 값 없음 — 바깥 스코프의 this |

우선순위는 `new` > `bind/call/apply` > `obj.fn()` > 기본 호출 순입니다.

### obj.fn()에서 this가 어떻게 나오는가

스펙에서 `obj.fn`이라는 표현식은 값이 아니라 **Reference Record**로 평가됩니다. `{ base: obj, name: "fn" }` 같은 형태입니다. 호출 연산자 `()`가 이 Reference를 받으면 `base`를 `this`로 사용합니다.

```js
const user = { name: "kim", hi() { return this.name; } };

user.hi();        // Reference{base: user} → this = user
(user.hi)();      // 괄호는 Reference를 유지 → this = user
const f = user.hi;
f();              // 값만 복사됨, Reference 소실 → this = undefined
(0, user.hi)();   // 쉼표 연산자가 값으로 변환 → this = undefined
```

`const f = user.hi`에서 `this`가 사라지는 건 버그가 아니라, **대입 과정에서 Reference가 값으로 풀리는 것**입니다. 메서드를 "꺼내는" 순간 `base` 정보를 버립니다.

### 화살표 함수는 this를 갖지 않는다

화살표 함수에는 `ThisBinding` 자체가 없습니다. `this`를 만나면 일반 변수처럼 렉시컬 스코프 체인을 타고 올라가 바깥 함수의 `this`를 찾습니다. 그래서 `call`/`bind`로도 바꿀 수 없습니다.

```js
const arrow = () => this;
arrow.call({ a: 1 }); // 여전히 바깥 스코프의 this
```

## 실제로 언제 쓰는가

**일반 함수 / 메서드를 쓰는 경우**
- 객체 메서드, 프로토타입 메서드처럼 호출한 객체가 `this`여야 할 때
- 생성자 함수
- `call`/`apply`로 다른 객체에 메서드를 빌려 쓸 때

**화살표 함수를 쓰는 경우**
- 콜백 안에서 바깥의 `this`를 그대로 쓰고 싶을 때
- `this`가 호출자에 따라 바뀌면 안 되는 이벤트 핸들러, 타이머

```js
class Timer {
  seconds = 0;

  start() {
    // 화살표: start()를 호출한 인스턴스의 this를 유지
    setInterval(() => { this.seconds++; }, 1000);
  }
}
```

반대로 **객체 리터럴의 메서드를 화살표로 쓰면** 안 됩니다. 객체 리터럴은 스코프를 만들지 않으므로 `this`는 모듈/전역 레벨의 값이 됩니다.

## 흔한 오해와 함정

### 1. 메서드를 콜백으로 넘기면 this가 사라진다

```js
class Cart {
  items = [];
  add(item) { this.items.push(item); }
}

const cart = new Cart();

// 수정 전
button.addEventListener("click", cart.add);
// 호출은 DOM이 하므로 this는 button (또는 undefined) → 에러

// 수정 후
button.addEventListener("click", cart.add.bind(cart));
button.addEventListener("click", (item) => cart.add(item));
```

React 클래스 컴포넌트에서 `this.handleClick`을 `bind`하던 이유가 정확히 이것입니다. JSX는 `onClick={this.handleClick}`처럼 **값만 넘기기** 때문에 Reference가 사라집니다.

### 2. 중첩 함수의 this는 바깥을 따라가지 않는다

```js
const order = {
  items: [1, 2],
  total: 0,
  calc() {
    this.items.forEach(function (n) {
      this.total += n; // 일반 함수 → 기본 호출 → this가 order가 아님
    });
  },
};
```

`forEach` 콜백은 `callback()`처럼 호출되므로 일반 함수의 `this`는 `undefined`입니다. 화살표 함수로 바꾸거나 `forEach`의 두 번째 인자 `thisArg`를 쓰면 해결됩니다.

### 3. bind는 한 번만 먹는다

```js
function who() { return this.name; }
const a = who.bind({ name: "A" });
const b = a.bind({ name: "B" });
b(); // "A"
```

`bind`가 반환하는 bound function은 내부 슬롯에 `this`를 고정해 둡니다. 다시 `bind`해도, `call`을 해도 바뀌지 않습니다. (`new`만 예외입니다.)

### 4. 클래스 필드의 화살표 함수는 공짜가 아니다

```js
class A {
  handle = () => this; // 인스턴스마다 함수가 새로 생성됨
}
```

`this` 문제는 해결되지만 메서드가 프로토타입에 공유되지 않고 인스턴스마다 복제됩니다. 수천 개 인스턴스를 만드는 경우가 아니면 대개 문제없지만, 상속과 `super.handle()` 호출이 안 된다는 점은 알아둬야 합니다.

### 5. 클래스 본문은 항상 strict mode다

`class` 안에서는 기본 호출 시 `this`가 `globalThis`가 아니라 `undefined`입니다. 그래서 같은 코드가 일반 함수에서는 조용히 `window`를 건드리고, 클래스에서는 `TypeError`를 던집니다. 에러가 나는 쪽이 오히려 안전한 쪽입니다.

## 정리

`this`의 핵심은 **"선언 위치가 아니라 호출 형태로 결정된다"** 는 것입니다. 점(`.`) 앞의 객체가 있는지, `new`/`call`/`bind`가 붙었는지만 보면 대부분 예측됩니다.

호출자에 따라 달라져야 하면 일반 함수, 바깥의 `this`를 그대로 가져가야 하면 화살표 함수를 쓰세요. 코드를 읽다 `this`가 의심되면 선언을 보지 말고 **호출하는 줄**을 찾아가는 습관을 들이면 됩니다.
