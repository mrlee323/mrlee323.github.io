## 첫 번째 실수

리뷰 AI 요약 기능의 프로토타입을 처음 만들 때, 가장 빠른 방법을 선택했습니다. 클라이언트 컴포넌트에서 OpenAI SDK를 직접 import해서 호출하는 방법이었습니다.

```tsx
// 이렇게 하면 안 됩니다
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.NEXT_PUBLIC_OPENAI_API_KEY, // 위험
  dangerouslyAllowBrowser: true,                  // 이 경고가 이미 답입니다
});
```

`dangerouslyAllowBrowser: true`라는 옵션 이름이 이미 답을 알려줍니다. SDK 자체가 "브라우저에서 쓰지 말라"고 말하고 있습니다. 그런데도 계속 진행하면 어떤 일이 생기는지 직접 경험했습니다.

---

## 클라이언트에서 LLM을 직접 호출하면 생기는 문제

### 1. API key 노출

`NEXT_PUBLIC_` 접두사가 붙은 환경변수는 빌드 결과물에 그대로 포함됩니다. 브라우저 개발자 도구에서 네트워크 탭을 열면 요청 헤더에 API key가 그대로 보입니다.

누구든 그 key로 LLM API를 호출할 수 있습니다. 요금은 우리 계정으로 청구됩니다.

### 2. 비용 통제 불가

서버 계층이 없으면 클라이언트가 얼마나 많은 요청을 보내는지 추적할 방법이 없습니다. 한 사용자가 1분에 100번 요청을 보내도 막을 수 없습니다.

실제로 rate limit 없이 프로토타입을 잠깐 돌렸을 때, 예상보다 훨씬 빠르게 API 크레딧이 소진됐습니다.

### 3. 프롬프트 노출

프롬프트 엔지니어링에 시간을 많이 씁니다. 어떤 시스템 프롬프트를 쓰는지, 리뷰를 어떻게 포맷해서 넘기는지가 결과 품질을 결정합니다. 클라이언트에서 호출하면 그 로직이 그대로 노출됩니다.

---

## Next.js Route Handler로 서버 계층 만들기

해결책은 단순합니다. 브라우저는 우리가 만든 Route Handler를 호출하고, Route Handler가 LLM API를 호출합니다. API key는 서버에만 존재합니다.

```
브라우저 → POST /api/ai/review-summary → Route Handler → LLM API
                                              (서버에서만)
```

### Route Handler 구현

```ts
// app/api/ai/review-summary/route.ts

import { NextRequest, NextResponse } from "next/server";

export async function POST(req: NextRequest) {
  try {
    const body = await req.json();

    // 요청 검증 (Zod, 다음 포스팅에서 다룹니다)
    const { hotelName, reviews, question } = body;

    // LLM 호출 (lib/ai/review-summary.ts)
    const result = await generateReviewSummary({ hotelName, reviews, question });

    return NextResponse.json({ ok: true, data: result });
  } catch (error) {
    return NextResponse.json(
      { ok: false, code: "INTERNAL_ERROR", message: "요약 생성에 실패했습니다." },
      { status: 500 }
    );
  }
}
```

Route Handler는 Next.js App Router에서 `app/api/` 경로에 `route.ts` 파일을 만들면 됩니다. `export async function POST`가 POST 요청 핸들러가 됩니다.

API key는 `OPENAI_API_KEY`처럼 `NEXT_PUBLIC_` 없이 선언합니다. 서버에서만 읽히고, 클라이언트 번들에 포함되지 않습니다.

### 클라이언트에서 호출하는 패턴

```ts
// lib/api/review-summary.ts

import type { ReviewSummaryRequest, ReviewSummaryResponse } from "@/lib/ai/schemas";

export async function fetchReviewSummary(
  payload: ReviewSummaryRequest
): Promise<ReviewSummaryResponse> {
  const res = await fetch("/api/ai/review-summary", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  });

  if (!res.ok) {
    const error = await res.json();
    throw new Error(error.message ?? "요약 요청에 실패했습니다.");
  }

  const json = await res.json();
  return json.data;
}
```

클라이언트는 `/api/ai/review-summary`로 fetch를 보냅니다. OpenAI SDK가 어떻게 생겼는지 전혀 모릅니다. LLM provider를 Claude로 바꾸든, 내부 캐싱 로직을 추가하든 클라이언트 코드는 변하지 않습니다.

### 컴포넌트에서 사용

```tsx
// app/components/review/ReviewSummaryPanel.tsx

"use client";

import { useState } from "react";
import { fetchReviewSummary } from "@/lib/api/review-summary";
import type { Review } from "@/types";

interface Props {
  hotelName: string;
  reviews: Review[];
}

export function ReviewSummaryPanel({ hotelName, reviews }: Props) {
  const [summary, setSummary] = useState<ReviewSummaryResponse | null>(null);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const handleGenerateSummary = async () => {
    setIsLoading(true);
    setError(null);

    try {
      const result = await fetchReviewSummary({
        hotelName,
        reviews: reviews.slice(0, 50).map((r) => ({
          id: r.id,
          content: r.content,
          rating: r.rating,
        })),
      });
      setSummary(result);
    } catch (e) {
      setError(e instanceof Error ? e.message : "알 수 없는 오류가 발생했습니다.");
    } finally {
      setIsLoading(false);
    }
  };

  // ... 렌더링
}
```

컴포넌트는 `fetchReviewSummary`만 알고 있습니다. 로딩, 에러, 결과 상태를 관리하고 결과를 UI로 보여주는 책임만 집니다.

## 서버 계층이 생기면서 가능해진 것들

Route Handler가 중간에 있으면 나중에 다양한 것을 추가할 수 있습니다.

**Rate limiting.** 같은 사용자가 단시간에 과도한 요청을 보내면 차단할 수 있습니다.

```ts
// app/api/ai/review-summary/route.ts
const rateLimiter = new RateLimiter({ max: 5, windowMs: 60_000 });

export async function POST(req: NextRequest) {
  const userId = getUserId(req); // 세션, 쿠키 등
  if (!rateLimiter.check(userId)) {
    return NextResponse.json(
      { ok: false, code: "RATE_LIMIT_EXCEEDED", message: "잠시 후 다시 시도해주세요." },
      { status: 429 }
    );
  }
  // ...
}
```

**Logging.** 어떤 요청이 들어왔고, LLM 응답에 얼마나 걸렸는지, 어떤 에러가 났는지 서버에서 추적할 수 있습니다.

**Caching.** 같은 숙소에 대한 요약은 하루 정도 캐싱해도 됩니다. 사용자가 수백 명이 같은 숙소를 보더라도 LLM은 한 번만 호출합니다.

```ts
// 간단한 인메모리 캐시 예시
const cache = new Map<string, { data: ReviewSummaryResponse; expiresAt: number }>();

function getCacheKey(hotelName: string): string {
  return `review-summary:${hotelName}`;
}

// Route Handler 내부
const cacheKey = getCacheKey(hotelName);
const cached = cache.get(cacheKey);
if (cached && cached.expiresAt > Date.now()) {
  return NextResponse.json({ ok: true, data: cached.data });
}
```

이 모든 것이 클라이언트 코드를 전혀 바꾸지 않고 Route Handler 내부에서만 추가됩니다.

---

## 정리

"일단 클라이언트에서 직접 호출하고 나중에 옮기자"는 기술 부채를 쌓는 가장 빠른 방법입니다. API key 노출은 "나중에" 고칠 수 없습니다. 이미 노출된 key는 폐기해야 합니다.

Next.js Route Handler는 LLM을 서버 뒤로 숨기는 가장 단순한 방법입니다. `app/api/` 폴더에 `route.ts` 파일 하나면 됩니다. 이 계층 하나가 보안, 비용 통제, 향후 확장의 기반이 됩니다.

AI 기능을 처음 붙일 때, 서버 계층은 선택이 아닙니다.
